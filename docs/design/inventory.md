# Juno design inventory

Every surface and component in the v1 design, with structure, states, measurements, copy, keyboard behaviour and the screenshot that shows it. Values are from the prototype (`docs/design/handoff/prototype/Threads v3.dc.html`) unless marked **[spec]** (SPEC.md wins over the prototype) or **[proposed]**. Token names refer to `docs/design/tokens.md`.

Screenshot references: `S01`–`S15` are `docs/design/handoff/screenshots/01-ui.png` … `15-ui.png`. References like `shot 07-message-hover-toolbar` are captures I took from the prototype (kept outside the repo in `/tmp/juno-design/shots/`, not needed to build; reproduce by opening the prototype).

Conventions that apply everywhere (SPEC §16):

- No `cursor: pointer`. Arrow cursor on buttons, rows, tabs, menu items. Text cursor only in editable text.
- Hover styles only under `@media (hover: hover)`. Hover-revealed actions also show on `:focus-visible` / `:focus-within`.
- Press: `scale(0.96)`, 150ms ease-out, never when disabled.
- Background-colour feedback at most 150ms.
- Icons: Lucide, stroke = surrounding text colour.
- Chrome is not selectable; message text and inputs are.
- Focus ring: 2px, offset 2px, keyboard only.
- Numbers use tabular figures.
- Sentence case. Buttons start with a verb.
- Context menus are native (spec). The prototype's DOM menus define the item order and labels; native menus cannot show the icons or the right-aligned hints ("⌘ click", "Stays unread"), so those are dropped or moved to the shortcut column.

## 1. Window and title bars

**Shows:** S01.

- Two panes: sidebar on the left, 384px by default (`--sidebar-width`), resizable and collapsible (below); workspace fills the rest. Root is `display: flex; height: 100%; overflow: hidden`.
- Root text: 14px, line-height 1.5, letter-spacing 0.01em, `--font-sans`, colour `--foreground-default`, background `--background`.
- Sidebar top bar: 44px, padding `0 10px 0 16px`, background `--background-subtle`. Traffic lights live here (Electron `titleBarStyle: 'hiddenInset'`; the prototype fakes them as 12px circles with 6px gaps). The bar is a drag region (`-webkit-app-region: drag`); each group of buttons inside is `no-drag` on its container, not on every button (performance.md 8.5).
- Workspace top bar: the tab strip, 44px, also a drag region. Border-bottom 1px `--border-default`, background `--tab-strip`, a step below the sidebar (§4).
- Sidebar top bar, left to right: traffic lights · **Collapse sidebar** (`sidebar-simple` 16) · **Back** (`caret-left` 16) · **Forward** (`caret-right` 16), each 30×30 radius 8, the same style as the title bar icons (§2.1), starting 78px from the window edge so the traffic lights keep their space; then the right-aligned group (§2.1). Back and Forward are disabled (opacity `--opacity-disabled`, no hover) when the active tab has nowhere to go. Names "Back ⌘[", "Forward ⌘]", "Hide sidebar ⌃⌘S"; each has a tooltip with the name and the shortcut as keycaps (primitives 14a). A long press on Back or Forward lists that tab's history as a native menu, as in Safari. [built] The press lasts 500ms; Back and Forward themselves act on click, not on mouse down, so a long press can become the menu. The menu names each entry by its tab title ("Home" for Home, "Topic" when the topic's header is not loaded).
- Sidebar right edge: 1px `--border-default`. **Resize**: a 6px hit area centred on the edge (no visible handle; `col-resize` cursor over it, the one place a non-arrow cursor shows besides text). Drag between `--sidebar-min-width` 312 and `--sidebar-max-width` 480; double-click resets to 384. While dragging, only the sidebar box's inline `width` changes (set from a pointer-move handler, written once per frame); rows are fluid, so nothing re-renders, and the width is saved on pointer up. [built] It is a plain width and not a CSS variable: an inherited custom property changed on the shell made Chromium restyle every element under it, 4.7 ms a frame on the large workspace (performance.md 1). The tab strip and topic column take the rest and re-centre.
- **Collapse**: ⌃⌘S, the collapse button, or View › Hide Sidebar hide the sidebar in one frame (no slide; under reduced motion it would be the same). Collapsed, the tab strip starts with the traffic lights' 78px, then Show sidebar, Back and Forward (the same 30px buttons), then the tabs. **Full screen**: macOS hides the traffic lights there, so the sidebar top bar starts at its 10px inset (`--sidebar-inset`) and the collapsed tab strip at its own 10px padding, with no 78px. [built] Main sends `window.fullScreen` on `enter-full-screen` and `leave-full-screen`, which arrive as the macOS animation ends (the lights are gone on entry and come back on exit), and the shift is one frame with no transition. A reload in full screen loads with `?fullscreen=1`, so the first frame already has no room for the lights. The state is saved. Dragging the edge below 200px also collapses it. [built] It collapses when the drag ends there, and the saved width is kept for the next show. The width and the hidden state are saved in `launch.json` with the theme, so the first frame after a launch already has them.
- Scrollbars: 10px, transparent track, thumb `--border-strong` with 3px transparent inset and radius 10 (`::-webkit-scrollbar`). Scroll containers use `overscroll-behavior: contain` so menus, popovers and the palette never scroll the page behind.

### 2.3 Quick filters and views

Row padding `0 10 10`, height 28, never taller. Two parts: a horizontal scroller (flex 1, min-width 0) with the pills, gap 2, and the **Unread** toggle fixed at the right, 6px after the scroller. `docs/design/sidebar-views/` has the mock.

- **The scroller** (`PillRow` in `@juno/ui`): `overflow-x: auto`, no visible scrollbar, `overscroll-behavior: contain` (a sideways swipe at an end never reaches Back or Forward, a wheel never reaches the list). A vertical wheel over it scrolls it sideways. When it overflows, the side it can scroll toward fades over 16px (`--space-4`): a sticky gradient in `--background-subtle` at each end, shown by a `scroll-state` container query, so no script watches the scroll. Keyboard focus scrolls the focused pill into view whole, ring included. The row keeps `--focus-ring-room` on every side for the pills' rings (`ringRoom`; its height is a pill plus the room above and below), and each fade also covers that room in solid colour, so a pill half under an end is cut where it would be without the room. A focused pill draws above the fade.
- **Pills**, 28px, radius 8 (`Button variant="filter"`): selected bg `--secondary-default`, fg default; unselected transparent, fg muted, hover fg default. Weight 500 in both, so selecting never changes a width.
  - **All**: text.
  - **Channels** (`hash` 14) and **DMs** (`user` 14): icon-only, 28×28. Tooltip and accessible name "Channels" and "DMs".
  - **A view**: its icon 14 in a 28×28 pill when it has one (tooltip and name are the view's name), otherwise its name as text, at most 120px (`--filter-pill-max-width`) with an ellipsis. The icon takes the view's colour (`--icon-tint-<accent>`, tokens 1.3a) when it has one, the same whether the pill is selected, hovered or not; without one it is the pill's muted grey.
  - **New view**: `plus` 14, 28×28, fg muted, tooltip and name "New view". Always last. A popover button (`aria-haspopup="dialog"`, `aria-expanded`), not a toggle: while the sheet is open for a new view it keeps its hover fill (`--surface-hover`) [decided 10-17].
- **Unread only** (outside the scroller, at the right): `notification` 14 (a box with a dot on its corner, the pills' own unread mark) in a 28×28 icon pill, the same `Button variant="filter"` as Channels and DMs, so its icon sits 7px in on every side as theirs does. Tooltip and accessible name "Unread only"; `aria-pressed` and the selected fill while it is on. No count and no dot. [10-15] Replaced the "Unread" text toggle.
- **Dot**: 5px `--hl` at the pill's top right (4px in from the top and right edge), absolute so it moves nothing; only its opacity changes. Channels and DMs: the group has unread topics the sidebar would show. A view: one of its topics has an unread mention (plain unread does not count). Never on the selected pill. The name says it: "Channels, unread", "Bots, unread mention".

- **Right-click a view pill** (native menu, §15.7): Edit view… · Move left · Move right · — · Delete view. Dragging a pill along the row reorders it (a 2px `--hl` caret shows where it lands); All, Channels, DMs and New view do not move.

### 2.5 Topic list

Scroll container, padding `0 8 16`, contained scroll.

### 3.1 Anatomy (comfortable density)

```
[tile 44]  [line 1: title ........................ time | Resolve]  height 22
           [line 2: Sender: preview, 1 line …  ○○○○ +2  @ count]
           [line 3: # channel ▢Reopened .................. | slot]  margin-top 3
```

Every Main (a channel's, a DM's or a group DM's) has two lines and no line 3:

```
[tile 44]  [line 1: #channel or name ▢Reopened ◌2 ... time]  height 22
           [line 2: text (no sender from the other person)  @ | count | Resolve]
```

- Container: `role="listitem"` in a `role="list"`, `tabindex` (roving), named by the title (`aria-labelledby`), `aria-current` when selected; Enter and Space open it. Not a button: a button's children are presentational, which would hide the Resolve button inside. Flex, gap 12, align start, padding `11 12`, a fixed height of 88px (80 compact: `--density-row-estimate` plus the padding), or 64px (58 compact: `--density-row-two-line-estimate` plus the padding) for every Main, chosen from the row's kind (`data-row-lines`), radius 10, transparent. ### Integration attachments

Message attachments use a thin token-tinted bar, linked title, mrkdwn body,
two-column fields (a field's bold first line is its label, shown above the value in the 12px muted tag style; the value is regular body text) and a small muted footer with time. The bar takes the status colour itself (`--info`, `--tint-resolved-fg`, `--warning`, `--danger`, or `--border-strongest` for none). URL actions are quiet
links; callback-only actions are plain text. Long bodies fade out at the cut and have Show more and
Show less, a ghost button whose text starts at the body's edge. Images reserve their aspect ratio within the existing thumbnail
caps; missing dimensions reserve a 3:2 box. Integration event summaries use
the attachment or header title for the topic fallback. Previews and search
include structured content, under the existing preview privacy treatment.
