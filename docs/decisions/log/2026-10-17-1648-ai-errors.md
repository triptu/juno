- 10-17 16:48 · ai-errors · Model errors are sorted into kinds (`@juno/ai-failure`, a new leaf package with no dependencies that both `@juno/ai` and `@juno/agent` use, so the agent does not reach `ai`, `domain` or `topic-art`): only network, timeout, rate limit, unavailable and server errors are retried, and an input refused for good (policy, bad request, too long, unknown model, key, credits) is kept in `ai_refusals` and not sent again until it changes. A policy refusal or an unavailable model gets one call to a fallback model from another maker, chosen in Settings › Juno (Gemini Flash by default, None allowed), as a second request with its own reservation rather than OpenRouter's `models` list, which falls back on any error and would be priced at the main model's rates.
