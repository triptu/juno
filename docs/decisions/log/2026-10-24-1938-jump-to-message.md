- 10-24 19:38 · jump-to-message · A jump to one message the store lacks in full (a search match, a Slack link, a cited reply) is its own command, `messages.loadAt`, and costs at most two Slack calls however deep the message is: in a thread, the page from the newest reply stored in full before it up to it, then, if that page does not reach it, the page that starts at it. It replaces asking for the page before the message, which judged a thread complete from counts while live replies were still landing and so fetched nothing, and otherwise filled forward up to 500 replies. Thread coverage gets no gap mark: the store's thread model has only counts and `complete_from`, so a window across the replies left between shows those on either side together (backlog).
