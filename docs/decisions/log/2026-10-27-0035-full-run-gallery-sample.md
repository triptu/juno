- 10-27 00:35 · Full runs reuse gallery walk records and check a fresh 5% sample · Tushar decided that a full run may trust the gallery walk records that affected runs already trust: it walks the fast check on every state whose walk-cache key changed plus a random 5% of the states with a reusable pass (a new seed each run, printed and recorded), and reuses the rest; cached rendering tests follow the same rule. A sampled state or test that fails fails the run and says the key missed an input. Every state is walked uncached when the last uncached walk on record is over seven days old, or with `--no-cache`. The record counts what was walked, reused (by the run that wrote each record) and sampled, and the release gate refuses a sampled gallery without those counts. Before, `GALLERY_SHIFT_ALL=1` walked all ~1,835 states in every full run, about 90 s of the gallery job. Measured on three cores with the records current: the gallery step took 25 s and 105 CPU-s against 100 s and 491 (83 states and 3 rendering tests sampled, 1,752 states and 48 tests reused), and the gallery job 35 s against 111 s.
