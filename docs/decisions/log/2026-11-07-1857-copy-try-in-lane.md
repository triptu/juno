- 11-07 18:57 · sm-out9 · A copy delete's try that waits in the send lane, and the action worker with it, is not modelled: the conformance spec queues no user change while a try may be in the lane (`copyTry`), and the engine keeps settling one action row at a time · The wait is set by the retry backoff against the post at the lane, which the harness can neither see nor control, so a trace committing to either order would fail on the other. The engine's order is right: one lane, one call at a time, and a change that waits goes once. Modelling the try would need the model to guess the engine's timer, and freeing the worker from the wait would need a concurrent action worker for no user-visible gain.
