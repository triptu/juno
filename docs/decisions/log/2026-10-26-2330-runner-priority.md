- 10-26 23:30 · Releases take laptop cores first · tstack's allocator takes a priority per request (`normal` or `high`): while a high request waits, a normal one starts only if the cores left after the high one's still fit it. Running jobs are never stopped, and markers of dead waiters expire after 60 s. `bun run release` runs at high priority; `--priority high` or `JUNO_PRIORITY=high` marks any `remote`, `verify:main` or `affected` run. Why: a release's full run waited behind ordinary agent runs.
