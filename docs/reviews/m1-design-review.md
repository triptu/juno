# M1 design review

Scope: `packages/tokens`, `packages/ui` and `apps/gallery` as built for milestone 1, judged against SPEC sections 16 and 17, `docs/design/tokens.md`, `primitives.md`, `inventory.md` and the handoff screenshots.

Method: ran `pnpm gallery:shots` (134 fixtures, light and dark, 2x). Looked at every screenshot and compared with the handoff screenshots S01 to S15. Then probed the running gallery in Chrome for things a screenshot cannot show: computed cursor, press scale, keyboard focus ring, tabular numbers, element sizes, and a text contrast sweep over every fixture (all text nodes, both themes, 4.5:1 threshold, disabled text ignored).

Screenshot paths below are relative to `apps/gallery/shots/` (git-ignored, regenerated by `pnpm gallery:shots`). Extra evidence taken during the review is in `docs/reviews/m1-design-review-assets/` (focus ring captures and `focus-contact-sheet.png`).

## Overall

The system is in good shape. It reads as the handoff design with Inter and Instrument Serif:

- Surfaces: cards use a 1px ring, popovers use the layered `--pop-shadow`, no hard borders on floating surfaces. Dark mode is the cool near-black palette and holds up everywhere.
- Control sizes, radii, weights and paddings match `tokens.md` (checked by measurement: Button 22/28/30/32/34/36, IconButton 20 to 36, Select 30, Segmented segment 24, Toast Undo 26, ContextPill 26, avatars 44 to 18, Surface radii 10/13/9/8).
- Press scale is `0.96` and is not applied when disabled. Focus ring is 2px, offset 2px, `#008AB3` light and `rgb(94,190,237)` dark, keyboard only, and clearly visible on every control tried (Button, Select, Checkbox, Slider, Segmented, Tab, ListRow button, reaction Chip, IconButton). Text fields and Textarea show focus as a coloured border plus 1px ring, as `primitives.md` specifies.
- Tabular numbers are on for unread counts, row times and nav counts. The three context tints (public, private, DM), the soft grey count tags and the serif page titles match the handoff closely. The serif at 36px reads at about the handoff's size.
- Text contrast passes 4.5:1 everywhere except the items listed below.

Eight items need fixing before views are built on top of these primitives. The rest is polish.

## Must fix before views are built

### 1. Checkbox and Slider show the text cursor

- Component and fixture: `Checkbox/checked`, `Slider/default` (all fixtures of both).
- Wrong: computed `cursor` is `text` on the native `input` for both. SPEC section 16: the text cursor appears only over editable text; everything else is the arrow. Select is correct (`default`). Probably a blanket `input { cursor: text }` rule from TextField that also reaches checkbox and range inputs.
- Should be: `cursor: default` on `input[type=checkbox]` and `input[type=range]`. Add a gallery or unit assertion that no fixture except TextField, Textarea, CodeBlock and selectable Text computes `cursor: pointer` or `text`.
- Evidence: `Checkbox/checked-light.png` (cursor not visible in a screenshot; measured in the browser).

### 2. "3 NEW" divider has no rule

- Component and fixture: `Divider/labelled-new`, `Divider/labelled-muted` (`LabelledRule`).
- Wrong: only the label renders. The rule span measures 0px wide because the flex container is only as wide as the label (49px). In S01, S03 and S04 the rule runs the full message column.
- Should be: `width: 100%` on the `labelled` style in `packages/ui/src/Divider.tsx` (or `alignSelf: stretch`), so the rule fills the row in `--hl-rule` (accent, 30%) or `--border-default` (muted).
- Evidence: `Divider/labelled-new-light.png`, `Divider/labelled-new-dark.png` vs handoff `docs/design/handoff/screenshots/01-ui.png`.

### 3. AvatarStack clips the initials

- Component and fixture: `AvatarStack/four`, `AvatarStack/two`, `AvatarStack/two-at-20`.
- Wrong: each avatar overlaps the previous by 4px, which cuts the last letter of the avatar below it. "DP" reads "DF", "MC" reads "MC" with a sliced C. The 1.5px `--background-subtle` ring is also almost invisible on the light paper, so the avatars look glued together rather than separated.
- Should be: at size 18 either show one initial per avatar, or reduce overlap to `-3` and drop initials to 7px at tracking 0, or use `--background` for the ring on `--background` surfaces so the ring reads as a cut. The ring colour must follow the surface the stack sits on (the prop already exists as `ring`; give the stack a `ringColor`/`surface` prop).
- Evidence: `AvatarStack/four-light.png`, `AvatarStack/four-dark.png`, `AvatarStack/two-at-20-light.png`.

### 4. TabStrip shrinks to its content, so the bottom border and the 230px tabs are wrong

- Component and fixture: `Tabs/two-tabs`, `Tabs/stealth`, `Tabs/with-page`, `Tabs/many`.
- Wrong: the `tablist` is 472px wide in a 720px frame, so the strip background and the 1px `--border-default` bottom border stop mid-frame. Tabs are 208px instead of the specified flex `0 1 230`, and titles truncate early ("Postgres 16 migrati…", "Thread l…", "Rina Sato …") when there is plenty of free space. Because the strip is not full width, the fixture cannot show the active tab merging with the page. The handoff (S01) shows a full-width strip with the tab titles intact.
- Should be: `TabStrip` is `width: 100%` (or `flexGrow: 1`) with `--titlebar-height` 44, border-bottom across the whole width; tabs `flex: 0 1 230px`, min 72px. Add a fixture with a page body under the strip so the active tab's bottom border (page colour) is seen overlapping the strip border. Check that "Postgres 16 migration plan" fits in 230px with Inter; if not, that is the tab truncation the tokens doc already expects.
- Evidence: `Tabs/with-page-light.png`, `Tabs/stealth-dark.png` vs `docs/design/handoff/screenshots/01-ui.png`.

### 5. Muted text on a selected row is 4.40:1

- Component and fixture: `ListRow/table-row` (selected row, light and dark).
- Wrong: the preview line ("Dev: Booked 2-4pm...") and the time ("4m") are `--foreground-muted` on the selected row background `--secondary-default`: 4.40:1 light, 4.41:1 dark. `tokens.md` section 1.7 says muted must not sit on `--secondary-*` (4.39:1) and to use `--foreground-subtle` there. Every sidebar and All topics row will have this state.
- Should be: when `selected`, meta and preview text use `--foreground-subtle` (5.65:1 light, 9.36:1 dark). Bake it into `ListRow` so feature rows do not each re-implement it.
- Evidence: `ListRow/table-row-light.png`, `ListRow/table-row-dark.png`.

### 6. Composer: buttons and text are not on one line, and the border is too faint

- Component and fixture: `Textarea/composer`, `Textarea/composer-grown` (the composer composition).
- Wrong, alignment: in the single-line composer the attach and send buttons (28px) are centred about 6px lower than the 22px text line (button centres at y=57, textarea centre at y=51 in the frame). The "+" sits visibly below "Reply". In the grown state the "+" aligns with the last line, which is correct, so the single-line case is simply off.
- Wrong, border: the composer's 1px border is `--border-default` (`#EFECE1`, measured), but `tokens.md` and the handoff use `--input-border` (`#D8D5CB`) for the composer. Next to `Textarea/plain` (which uses `--input-border`) the composer outline is almost invisible on paper. In S01 the composer outline is clearly visible.
- Should be: align buttons to the first-line centre for one line (`align-items: center` when not grown; `flex-end` only when the text wraps), and border `--input-border` with the focus colour on `:focus-within`.
- Evidence: `Textarea/composer-light.png`, `Textarea/composer-dark.png`, `Textarea/plain-light.png`.

### 7. Slider thumb is nearly invisible against the track and page

- Component and fixture: `Slider/default`, `Slider/high`, `Slider/low`.
- Wrong: in light mode the thumb is pale (`--surface-default`) on a pale track and paper: only a faint ring defines it. In dark mode the thumb is dark on a dark track, visible only against the filled part. The handoff Notifications slider (S12) has a solid dark thumb. Non-text contrast for the thumb is under the 3:1 guideline.
- Should be: thumb filled with `--foreground-default` (dark on light, light on dark) with a 2px `--background` ring (the 14px size stays), track unfilled `--secondary-active`, fill `--foreground-default`. This also matches `primitives.md` section 12 ("filled part in `--foreground-default`").
- Evidence: `Slider/default-light.png`, `Slider/low-dark.png`, handoff `docs/design/handoff/screenshots/12-ui.png`.

### 8. Fixture frames cut content, so some states cannot be reviewed

- `Popover/account-menu`: the 640x640 frame cuts the menu after "Sign out"; the bottom padding and radius are not visible. Make the frame tall enough (about 340px content plus anchor).
- `Chip/all-variants` does not include the `strong` unread-count variant on a `--secondary-default` row, the `dashed` stealth pill, or the `success` chip next to each other on the same surface; add them so the contrast rule in item 5 is covered by a fixture.
- `TextField/title` is 420px wide and the placeholder is cut ("...if empt"). Use `width="full"` in a 640px frame, as in the New message page (S08).
- Also add the missing states that views will need, all in light and dark: hover (forced with a class), pressed (`scale .96`), disabled for IconButton, Segmented, Select, Checkbox and Slider, invalid text field. Right now only Button has `disabled`, `dimmed` and `pressed`.
- Evidence: `Popover/account-menu-light.png`, `TextField/title-light.png`.

## Polish later

Ordered by how visible they are.

### 9. Dark Segmented selected segment is darker than its track

- `Segmented/digest`, `Segmented/now`, `Segmented/silent`, dark. Track is `--surface-hover` (`#1F2123`); the selected segment is `--surface-default` (`#1B1C1D`), so it looks recessed rather than raised. Light mode is right. Use `--secondary-default` (`#27292B`) plus `--shadow-sm` for the selected segment in dark, or keep the text colour change as the only signal and add a 1px `--border-strong` ring. Evidence: `Segmented/digest-dark.png`.

### 10. Raised button has almost no edge on light paper

- `Button/raised`, `Button/all-variants` (Raised), light. `--surface-default` on `--background` plus `--shadow-sm` (4% black) gives no visible edge; "Fix and send" reads like a ghost button. In the handoff (S04) it has a clear hairline. Add the `--card-ring` (1px ring) to the raised variant. Dark is fine. Evidence: `Button/raised-light.png`.

### 11. Avatar initials contrast is under 4.5:1

- Dark: midnight hue 3.19:1, claret 3.72:1, emerald 4.39:1. Light: plum 3.7, emerald 3.73, jordy 3.47, rose quartz 4.34. `tokens.md` section 1.6 accepts this for decorative initials. Where the avatar carries the only identity (mention picker, To picker, message headers) it is worth raising the foreground mix: for dark use `color-mix(<hue> 40%, var(--foreground-default))`, for light light-hue avatars use 75% hue mixed into `--foreground-default`. Keep the "skip yellow" rule. Evidence: `Avatar/all-hues-dark.png`, `Avatar/all-sizes-dark.png`.

### 12. "To" label sits higher than the field text

- `TextField/to-empty`, `TextField/to-set`. The "To" label baseline is about 1.5px (css) above "Channel or person" and the context pill text. Align both to the same baseline (`align-items: baseline` or a shared line-height). Compare S08. Evidence: `TextField/to-empty-light.png`.

### 13. Card fixture uses the wrong source icon

- `Card/waiting-on-you`: the source "Rina Sato · Staff backend" is a private channel in the handoff (S10 shows the lock icon). The fixture shows `#`. Use the lock so the fixture documents the right pairing; also check that Card takes `sourceIcon` from the context kind, not a hard-coded hash. Evidence: `Card/waiting-on-you-light.png`.

### 14. Mono font differs from the token doc

- `Text/all-roles`, `Kbd/all`, `CodeBlock/prompt`: monospace renders as the system face (Menlo or SF Mono; `--font-mono` is `ui-monospace, 'SF Mono', Menlo, ...`). `tokens.md` section 2.1 says JetBrains Mono 400/500 bundled locally. Either bundle it (consistent across machines, hyphens read as hyphens, not en-dashes as in "preview-envs") or update `tokens.md` and `fonts.css` to say system mono is intended. Decide once; do not leave the two disagreeing.

### 15. Small items

- `Surface/toolbar` fixture uses padding 6 with radius 9; `tokens.md` says toolbar padding 2 around 6px buttons (outer = inner + padding). Popover is radius 13 with 6px padding and 6px items (12 by the nesting rule; the doc allows 13). Palette (14 = 8 + 6) and segmented (7 = 5 + 2) nest correctly.
- `Kbd/all`: the "⌘," hint in the account menu is hard to read at the mono 10px size; use 11px for plain hints.
- `Icon/all-sizes`: 11px and 12px icons look heavier than the 16px ones. Check `strokeWidth`; at 11 to 13 use 1.75 or `absoluteStrokeWidth` so they do not look bold next to 11px tag text.
- `Button/disabled` and `Button/dimmed` primary in dark mode: label 2.7:1 (exempt as disabled, but the dimmed Send is a primary action the user sees often). Prefer `--opacity-disabled` 0.4 on the surface only and keep the label at `--accent-foreground` so it stays at least 3:1.
- Dark Resolved chip (`Chip/status-resolved-dark.png`) passes but is the dimmest coloured text in the set (green on near-black). Keep an eye on it if Inter 500 renders lighter at 12px.
- Focus ring on `Slider` wraps the whole control with a 2px offset oval; fine, but make sure the thumb gets its own visible state when the thumb is the focused element in the app.
- Narrow and wide widths: the gallery frames are fixed width (720 to 960 css), so responsive behaviour of `Page`, `PageHeader` (the trailing slot wraps under the title via `flexWrap`) and `TabStrip` was not exercised. Add one 480px and one 1400px frame for Page and Tabs.
