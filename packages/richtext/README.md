# @juno/richtext

Pure text handling between Slack and the UI. See `docs/architecture.md` section 9.

## Public API

- Incoming: `messageBody(content, lookups)` turns a message (`{ text?, blocks?, files?, attachments? }`, which a decoded `@juno/slack-schema` `Message` satisfies) into a `MessageBody`. `rich_text` blocks win; mrkdwn `text` is the fallback. `bodyFromBlocks`, `bodyFromMrkdwn` and `mrkdwnInlines` are the parts.
- `MessageBody` is a tree of blocks (paragraph, quote, code, list, heading, divider, file, table) and inlines (styled text, link, user, channel, usergroup, broadcast, emoji, date, break). Mentions arrive already named through `Lookups`. A person with no name reads "Someone"; a user group with no handle reads the `|@handle` label from the text, else "@group", never its id. A usergroup inline carries the group's `name` for a tooltip and `isMine` when `Lookups.myUsergroups` lists it. A code block whose first line is only a language tag (```` ```ts ````) carries the tag's language as `language` and `tagLine: true` (`codeBlock`, through `@juno/highlight`'s `splitLanguageTag`). `text` keeps the tag line, so `plainText` (the edit field, the fallback text, edits sent to Slack) has the code as written. What people read leaves it out, as the view does: `previewText` (row and Home previews) and `readableText` (notification bodies, search snippets).
- Tables: a Slack `table` block becomes a `table` block: `rows` of cells, every row as long as the longest (short rows end in empty cells), each cell the inlines a paragraph holds (styles, mentions, links, emoji, inline code; a cell's sections, list items and code one per line). `raw_text` and `raw_number` cells keep their `text`, a `null` cell is empty, and an unknown cell keeps its `text`. `columns` keeps Slack's `column_settings` by index (`align: 'center' | 'right'`, `wrap: true`; left and unknown alignments are the default) and is present only when one is set; `caption` and `showCaption` keep `caption` and `is_caption_visible`. The first row is the header, as Slack's client draws it. A table with no rows gives nothing, so a message of only that falls back to its `text`. An `unknown` block whose `raw` now decodes as a known block (a table stored by a version before tables, `{ type: 'unknown', raw }` in `blocks_json`) is read as that block, so cached messages need no resync. `tableText(rows)` writes rows as tab-separated lines (a tab, line feed or carriage return in a cell becomes a space); `plainText` uses it for whole tables and the view for a copied selection.
- Text views: `plainText` (as written), `readableText` (as shown: no code tag line), `previewText`, `previewLine` (quotes stripped, no code tag line), `inlineText`. A table, in `plainText` and `readableText` (copy, search, Ask Juno, notification bodies), is one line per row with its cells split by tabs, as a spreadsheet takes a paste; a tab or line break inside a cell becomes a space. `previewText` and `previewLine` leave tables out, so a message with words shows its words; a message whose only words are in a table reads "Table: " and its first row with words, cells split by commas ("Table: Service, Status, Owner"), or "Table" when no cell has any, so a preview is never empty.
- Markdown files: `bodyFromMarkdown(text)` reads a Markdown file (the media viewer's text items) as a `MessageBody`: ATX and setext headings, paragraphs, quotes, bullet, ordered and task lists, fenced code with its language, rules, and inline bold, italic, strike, code, links and bare links; images become links, so nothing is fetched. It reads in one pass, linear in the text, so an unclosed `[`, `` ` ``, `<` or marker repeated through a large file costs no more than any other text. `findLinks` looks for a link's wrapping markers only in the 256 characters before it.
- Outgoing: `composeOutgoing(text, targets)` turns composer text into `rich_text` blocks plus a fallback `text`. People and channels the composer picked arrive encoded as `<@U…|Maya>` and `<#C…|eng>` and are sent by id; an edit's `@Name` and `#channel` are found through `targets`; `> ` lines become quotes.
- Markup (`markup.ts`, SPEC section 8): Slack's `*bold*`, `_italic_`, `~strike~`, `` `code` ``, ```` ``` ```` code blocks and `> ` quote lines, read as Slack's client reads them with "Format messages with markup" on. A marker opens at a line start or after a character that is not a letter or digit, with no space after it, and closes at the nearest same marker with no space before it and no letter or digit after it; a doubled marker is text at either end (including `*bold**`); boundaries read Unicode code points; backslashes are literal; styles nest and stay on one line; nothing inside code is markup; mentions, links and shortcodes hold no markers. Three backticks open a code block anywhere outside a quote line and the next three close it, across lines; an unclosed or empty one is text. One grammar serves three callers: `composeOutgoing` sends styled runs as `text`, mention, link and emoji elements with a `style`, a code block as `rich_text_preformatted` with `border: 0` (only picked mentions and linked words are elements inside it), and keeps the markup as typed in `text` with a code block as "```code```" (research section 5, "Styles, observed live"); typed URLs and emoji inside code stay text; explicitly linked words keep their link. `markupLayout(text, opaque)` gives the field's look (styled runs, markers, code blocks, quote lines), with the picked names and linked words it shows as `opaque`. `toggleMarkup(text, selection, style)` is the edit a formatting key makes.
- Editing: `editMarkup(content, lookups)` writes readable markup, with one marker pair for adjacent elements of the same style and no escaping. `composeEdit(text, original, lookups, targets)` keeps unchanged whole paragraphs, quotes, list items and code blocks exactly as Slack sent them. Changed blocks are parsed as new markup, without inline placeholders. Thus editing a paragraph containing literal `*word*` may make it bold; editing another paragraph keeps the original literal text. An unchanged edit returns the original blocks. Blocks the field does not show (a table, a bot's layout blocks) are not in `editMarkup`'s text; `composeEdit` sends them back unchanged in their place among the edited blocks, with the words typed before a block's place going before it (inside the changed text, after as many line breaks as came before it). A message with no `rich_text` starts the field from its `text`. `composeEdit` returns `EditedMessage`, whose `blocks` may hold any block. Engine edits must call `composeEdit`, not `composeOutgoing`.
- Links: `findLinks(text)` finds URLs with a scheme, email addresses and bare domains on a short list of top-level domains ("example.com", not "index.ts"), trimming the sentence's closing punctuation and a markup marker that closes an open style on the line (`_https://example.com/a_b_` links `https://example.com/a_b`); `linkOf(text)` says whether a paste is one link. `composeOutgoing` sends them as Slack's client does (research section 5): a URL typed with its scheme as `{ type: "link", url }` and `<url>`, an address or domain with its scheme added and its text kept (`<http://example.com|example.com>`), and the composer's `<url|words>` as `{ type: "link", url, text }`. An edit's linked words are linked again through `targets.links`. Incoming text elements that hold a URL (bots, Juno before links) render it as a link too, except in code.
- Emoji: the shortcode table and helpers (`emojiUnicode`, `reactionDisplay`, `PICKER_EMOJI`, `QUICK_REACTIONS`). `customEmojiLookup(rows)` resolves workspace image URLs and aliases from the `emoji` table; missing targets and cycles keep their shortcodes. Pass the lookup as `Lookups.emoji`. `workspaceEmoji(rows, catalog)` uses the same resolver to build one canonical entry per image owner or standard target, with searchable aliases. Cycles and missing targets are omitted. The composer uses these resolved entries too. The standard catalog is supplied by the lazy caller so alias resolution does not pull it into the startup bundle. `emojiKeywordData` holds each standard emoji's search words, one line per catalog emoji in its order, with curated chat words, then `|` and broad English CLDR words, then `|` and the words of everyday phrases (`scripts/emoji-catalog.mjs` writes both files); only search imports it. The phrases ("ugh, so done, over it" for 😩) were written once by a model with `scripts/emoji-intent.ts` into `scripts/emoji-intent.json`, which is checked in; the `intentOverrides` list in `emoji-catalog.mjs` replaces the model's phrases for an emoji and is where bad ones are fixed. Flags and keycaps have none. Regenerate both with `node scripts/emoji-catalog.mjs` (pinned emoji-datasource 16.0.0 and CLDR 48.2.0); offline, pass the three JSON input paths shown in the script. The CLDR notice is in `apps/desktop/THIRD_PARTY_NOTICES.txt`, included in the packaged app.

Unknown inline elements (`file`, `canvas`, `message_mention`, future ones) decode to `{ type: 'unknown', raw }` in the schema; richtext keeps their `text` or `fallback`.

`date` inlines carry epoch seconds, the Slack format, readable fallback text and an optional link. Dates without fallback text use ISO text. `file` blocks carry `id`, `name`, `mimetype` and optional positive `width`/`height`, using original dimensions before thumbnail dimensions. Views reserve the image box from these fields and resolve the id through main. Legacy attachments keep their title, text and fields; fallback text is read only when those are absent. File names appear in plain text and previews.

## Must not

- Import anything but `@juno/slack-schema`: its types, and the `Block` schema, to read a stored unknown block again. No React, no I/O, no store, and no `effect` beyond `{ Schema }` (`check-deps` enforces it).
- Define Slack payload types of its own. They come from `@juno/slack-schema`.

## Testing

`pnpm --filter @juno/richtext test`. Table-driven tests with real payload shapes: `decode.test.ts` (a payload decoded with `Schema.decodeUnknownSync(Message)`, including an unknown element, then rendered), `rendering.test.ts`, `tables.test.ts` (table blocks and their text views), `outgoing.test.ts` (the markup rules and the edit round trip too), `edit-roundtrip.test.ts` (Slack-origin and generated edit preservation), `markup.test.ts` (the formatting keys and the field's look), `links.test.ts`, `emoji.test.ts`, and `content.test.ts` (dates, files, attachment text and workspace emoji). Use redacted or invented text, never real message content.

Integration attachments retain titles and links, mrkdwn bodies, two-column fields,
context, images, footer dates and URL actions. A shared Slack message (`is_share`
or `is_msg_unfurl` with a `from_url` permalink) gets a `source`: its place's kind
and name from the `place` lookup, the permalink, and `thread` when the link carries
another message's `thread_ts`; its footer is then only the date. Without a known
place the footer is Slack's own text as a link to the permalink. Fallback text is used only when
there is no structured content. `messageTitle` uses a structured title for an
empty root or an integration event summary. Otherwise it keeps the original
mrkdwn so title readers can resolve mentions when names arrive. Unknown blocks retain text and URL
buttons become links; Juno never invokes interactive callbacks.

## Slack-origin edit coverage

The shapes below come from [research section 5](../../docs/research/slack-data-access.md#5-messages-content-and-rendering) and the fake server’s rich-text fixtures. `test/edit-roundtrip.test.ts` checks them with invented content, plus 150 generated combinations unchanged, with another paragraph edited, and with the paragraph itself edited and compared against the ordinary markup parser.

| Original shape | Edit rule |
| --- | --- |
| Plain `*literal*` | Keep an unchanged paragraph verbatim; parse markers normally in a changed paragraph. |
| Plain `foo`, bold `bar`, plain `baz` | Preserve an unchanged paragraph; a changed one follows markup word boundaries. |
| Code containing a backtick or fences | Keep an unchanged code block; parse edited code with normal fence rules. |
| Styled whitespace, mentions, links, dates and invisible elements | Keep them in unchanged blocks, including their metadata; no inline preservation inside changed blocks. |
| Multiline quote and ordered list | Preserve unchanged quotes and list items. |
| Adjacent equally styled text and emoji | Write a single shared marker pair. |

New messages use `composeOutgoing`. Only edits have original elements to preserve. The fallback `text` is composed from the edited source; `blocks` remain authoritative.
