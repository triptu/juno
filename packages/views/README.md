# @juno/views

Feature views: React components built from `@juno/ui` that take view models and callbacks and nothing else. Containers in `apps/desktop/src/renderer/containers/` wire atoms to them. See `docs/architecture.md` sections 1 and 8, and `docs/development.md` ("Adding a feature").

Every view has a `<View>.fixtures.tsx` next to it, registered in `src/fixtures.ts`. Group its states under headings in product words (`Data: loading, empty, error, long`; `Session: expired`) as `@juno/ui`'s README shows. List only states the view's container can produce today: the lines and props its container passes, not copy it might pass later. A loading state holds still; nothing resolves on a timer.

## Must not

- Import `@juno/state`, `@juno/engine`, `@juno/store`, `electron`, Node built-ins or `effect` (`check-deps` enforces this for any `views/` directory).
- Mention `window.juno`. A container passes a callback.
- Hold state beyond local UI state such as a hovered or open flag.
- Use raw colours or sizes. Values come from `@juno/tokens` through `@juno/ui` primitives; see the stylex skill.
- Take `style` or `className`.

## Testing

Visual and behaviour checks run in the gallery, not in the package: `pnpm gallery` to look, `pnpm gallery:shots` for screenshots, `pnpm test:gallery` for behaviour (mouse-down activation, cursor rule, state switcher, no layout shift on hover, press or focus, and a message thumbnail that arrives late or fails). In the gallery a view is one state per address (`#/SignInView?__state=failure/keychain`), and `j` `k` `[` `]` move between states and components. A view's user flow is covered by an e2e spec against the built app.

`UpdateSettings` is the dumb Settings › About update setting, the update line (Restart to update, or Download the new version for an unsigned build) and the "What's new" changelog. Its container supplies availability, enabled state, the offer, the notes and callbacks.

Home's composer, Recent and destination chip stay in the startup bundle because Home is the launch tab. `DestinationLists` loads on idle, and the chip also warms it on hover and focus.

Deferred views use `chunk` from `@juno/ui`, also re-exported here for desktop containers. Frequent rows reserve their final row heights while loading; picker popovers mount their frame and content together.

Unfurl cards retain author and service icons, body text and source links. Their images load through the bounded main-process image route and collapse on failure. A shared Slack message's footer names its place, as a quiet link that opens the message (`SharedPlace`). The AttachmentCard gallery includes X, YouTube, generic, failed and shared-message previews.

Home’s missed-huddle row uses the conversation tile and existing row, with "Lasted 12 min · 18m" below its factual title.

`EmojiPicker` windows its grid with TanStack Virtual. Custom entries carry a canonical name, image URL and searchable aliases. Workspace follows the standard categories. Browse and search mount nearby rows plus the focused row. Failed images keep their cell and show a neutral placeholder in the same fixed box, with their name in the tooltip and accessible label. Search shares the composer ranking, and selected names resolve through aliases within their standard or workspace kind. Prepared `data` comes from the container; known recent names retain their cells while images arrive.
