# @juno/views

Feature views: React components built from `@juno/ui` that take view models and callbacks and nothing else. Containers in `apps/desktop/src/renderer/containers/` wire atoms to them. See `docs/architecture.md` sections 1 and 8, and `docs/development.md` ("Adding a feature").

## Public API

- The views: `Shell` (the two panes, or a drag strip over a page when signed out), `Sidebar` (title bar icons, nav, quick filters that switch on mouse down and name their dot ("Channels, unread"), a `status` slot under them, scope chip; takes the list as children), `TopicList` (sticky Pinned and Recent labels over rows the owner renders, the empty states with their next step, arrow-key focus; `onRowFocus` tells the owner which row has focus for the roving tabindex), `TopicRow` (one chat-style row from a contract `TopicRow`, memoized; the Resolve check in a reserved slot; the tile is `TopicArt` from `row.art` for every topic but a DM's Main, which keeps the person's photo), `AccountMenu` (the avatar popover's content), `Workspace` (tab strip placeholder over the empty page), `SignInView`, `SessionView`, `EngineStatusView` (the diagnostics line), `EngineNotice` (the status line under the sidebar's filters: offline, rate limited, or stopped with Restart), `AppInfoView`, `AppearanceSettings` (theme and accent; in the account menu until Preferences exists), `ChannelIconPicker` (not wired yet), each with its props type.
- The topic view (M4, `docs/plans/m4.md` WP4), each a dumb view over the contract's `TopicDetail`, `MessageView`, `ThreadSummary` and `Person`:
  - `TopicView` (the frame: `header`, the list as children, an optional `pill` floated over the list's bottom edge, and the `composer` slot at the bottom).
  - `TopicHeader` (context pill, Main's "Threads" button with its `Popover` and the `threads` content, then the 32px `art` slot and the title: "#eng · Main" with its sub line, or the title with the AI sparkle and double-click rename through `onRename`). Pin, Resolve and More arrive in M5; the header leaves the room.
  - `MessageList` (the centred 800px column in a `ScrollArea`; rows in flow with `content-visibility: auto`; the "N new" divider before `dividerBefore`; the fixed "Loading older messages" slot; the pending (nothing yet, for the first 300 ms of an open), loading, offline and empty states; a roving tabindex with arrow keys; `scrollRef` and `anchorRef` for the container, which owns every scroll decision; `renderToolbar` for the hover toolbar, which the app does not pass until M6).
  - `Message` (memoized; the avatar column with the time on hover for a continuation, the name and time on a group start, the body, files, reactions, Main's thread link, the mention tint, and the reserved toolbar slot inside the row's box), `MessageBody` (paragraphs, quotes, code, lists, headings, rules; `@person` chips in the person's hue, `@you` in the accent, `#channel` chips that call `onChannel`, links through `onLink`, custom emoji, `date` elements formatted in the reader's time zone; an emoji-only message is drawn larger), `Reactions` (chips; plain labels until `onToggle` is given), `Files` in `FileCard.tsx` (a thumbnail in a box of its final size from `thumb`'s dimensions, a fixed-height card otherwise), `ThreadLink` ("2 replies · Title ›", mouse-down activation), `NewDivider`, `NewMessagesPill` ("2 new messages" or "Jump to latest"), `HoverToolbar` (quick reactions, More reactions, Quote, Reply in thread in Main; icon only), `ActiveThreads` (the list behind "Threads": title, reply count, time, unread count), `ComposerSlot` (inert, at the composer's single-line height).
  - `Workspace` now takes `tabs` (`WorkspaceTab`: id, title, a kind or page icon, and `art` for the 15px icon slot), `activeId` and the tab callbacks; with no tabs it shows the empty state.
- The Juno chat (`src/juno-chat/`, SPEC §13, inventory §12), each a dumb view over `@juno/agent-contract`'s chat models, called back through one `ChatActions` object and one `CardCommand` union (`commands.ts`), so a card button is one command and the container maps it to one RPC:
  - `JunoChatList` (the 720px column in a `ScrollArea`; rows in flow with `content-visibility: auto`; one `ChatRow` switch over the `ChatItem` union; fixed edge slots for `moreAbove` and `moreBelow`; the empty state; the AI-off line at the end; `scrollRef`, `anchorRef`, `topEdgeRef` and `bottomEdgeRef` for the container, which owns every scroll decision).
  - `OwnerBubble` (the owner fill from the `chat` token group, the tail on a group's last bubble, the time on hover, and the delivery line in an 18px slot that is always there under a group's last bubble, so a line arriving or leaving moves nothing; "Queued" fades in after `--delay-queued` through CSS, not a timer), `JunoBubble` (the mark beside a group's last bubble, plain text with recall citations as `TextButton`s, the cards at column width through `renderCard`, the ending line in the same fixed slot; an empty body shows the ending line alone), `StatusBubble` (the three dots on a CSS loop, the status text fading in on each change, Stop in a reserved slot shown on hover or focus), `Note`, `GroupLabel`, `DaySeparator`, `EmptyChat`.
  - `cards/`: `ChatCard` is the shell every kind shares (header, body, the "Because" and "may already have happened" lines, and a 30px footer that holds the buttons while open and the after-line once settled, so a click never changes the card's height); one file per kind, registered by `_tag` in `cards/index.tsx`. A `sendMessage` row keeps its text box geometry after Send and fills a result slot that was there from the start. A `change` field's "Show all" makes the clamped box scroll rather than grow.
  - `JunoComposer` (controlled draft; Enter sends, Shift Enter adds a line, Esc with an empty draft calls `onEscape`; disabled only for AI off, update needed and another device; `inputRef` for ⌘J), `JunoHeader` ("Juno", the one banner chip with Resume or Review as a text button, the More menu with the six pages), `RemoveSheet` (the local sheet's panel; the container places it in a modal layer), `TextButton` (a word that acts inside a line of meta text), `JunoMark` (the 28px seated j).
  - Spacing: 2px inside a group, 8px between groups plus the 18px line slot under each group's last bubble, 20px around a day label.
- The Juno pages (`src/juno-pages/`): `ScheduledPage`, `RemembersPage` (the pin under edit is `editing`; its draft is the renderer's), `MemoryPage`, `ActivityPage`, `ConnectionsPage`, `JunoSettingsPage`, `ReviewPage` (renders the pending cards through `renderCard`), each on the `Page` shell with `Surface kind="group"` and `ListRow`s. `src/juno-pages/fixtures.ts` holds their invented data.
- `Sidebar` takes `junoUnread` (the soft grey count on the Juno item) and `junoBusy` (the sparkle turns duotone while a job runs).
- `src/juno-chat/fixtures/data.ts`: invented places, topics, every card kind in every status, and transcripts (the mock's conversation, long text, right-to-left, every card at once, a failed send, a stopped run, proactive groups, the New divider).
- `relativeTime(at, now)`, `messageTime(at, now)` ("9:12", "Yesterday", "Sat", "Oct 3"), `fullTime(at)` (the tooltip), `dayLabel(at, now)` (the chat's day separator), `slackDate(timestamp, format, now)` (a Slack `date` element's tokens), `hueFor`, `initials`: formatting helpers, repeated from `@juno/domain` where domain has them because views cannot depend on it.
- `src/fixtures/topics.ts`: invented `TopicRow` view models shaped like the fake Slack seed, shared by the sidebar and row fixtures. `src/fixtures/messages.ts`: invented headers, message windows (a long thread, Main with thread links, mentions of you, right-to-left, emoji only, hostile content, files) and active threads, with builders for bodies, reactions and files. `PENDING_PICTURE` points at the request the gallery server holds open, for a thumbnail that never arrives.
- Copy lives in the views and their fixtures and follows `docs/design/friendly-layer.md` §7 within SPEC §17: short titles, one-sentence bodies, no exclamation marks, "Juno" or "I" only on the sign-in and Juno surfaces.
- `TopicArt`, re-exported from `@juno/ui` for the header and tab containers: `<TopicArt topicId={id} recipe={detail.art} size={20} />` in the topic header, `size={16}` in a tab. The recipe is `TopicDetail.art` or `TopicRow.art` (`topicArtAtom(id)` in `@juno/state` gives it for any topic); absent means the Tide placeholder, which the component draws itself from the id.
- `applyTheme`, `accentNames`, `defaultAccent`, `AccentName`, `ThemeName`, re-exported from `@juno/ui`. The desktop app does not depend on `ui`, so it reaches the theme entry point here.
- `@juno/views/fixtures`: `fixtures`, every view's fixture sets keyed by view name. The gallery renders them, and each gets a screenshot in light and dark.

Every view has a `<View>.fixtures.tsx` next to it, registered in `src/fixtures.ts`. Group its states under headings in product words (`Data: loading, empty, error, long`; `Session: expired`) as `@juno/ui`'s README shows. List only states the view's container can produce today: the lines and props its container passes, not copy it might pass later. A loading state holds still; nothing resolves on a timer.

## Must not

- Import `@juno/state`, `@juno/engine`, `@juno/store`, `electron`, Node built-ins or `effect` (`check-deps` enforces this for any `views/` directory).
- Mention `window.juno`. A container passes a callback.
- Hold state beyond local UI state such as a hovered or open flag.
- Use raw colours or sizes. Values come from `@juno/tokens` through `@juno/ui` primitives; see the stylex skill.
- Take `style` or `className`.

## Testing

Visual and behaviour checks run in the gallery, not in the package: `pnpm gallery` to look, `pnpm gallery:shots` for screenshots, `pnpm test:gallery` for behaviour (mouse-down activation, cursor rule, state switcher, no layout shift on hover, press or focus, and a message thumbnail that arrives late or fails). In the gallery a view is one state per address (`#/SignInView?__state=failure/keychain`), and `j` `k` `[` `]` move between states and components. A view's user flow is covered by an e2e spec against the built app.
