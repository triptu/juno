# @juno/views

Feature views: React components built from `@juno/ui` that take view models and callbacks and nothing else. Containers in `apps/desktop/src/renderer/containers/` wire atoms to them. See `docs/architecture.md` sections 1 and 8, and `docs/development.md` ("Adding a feature").

## Public API

- The views: `Shell` (the two panes, or a drag strip over a page when signed out), `Sidebar` (title bar icons, nav, quick filters that switch on mouse down and name their dot ("Channels, unread"), a `status` slot under them, scope chip; takes the list as children), `TopicList` (sticky Pinned and Recent labels over rows the owner renders, the empty states with their next step, arrow-key focus; `onRowFocus` tells the owner which row has focus for the roving tabindex), `TopicRow` (one chat-style row from a contract `TopicRow`, memoized; the Resolve check in a reserved slot), `AccountMenu` (the avatar popover's content), `Workspace` (tab strip placeholder over the empty page), `SignInView`, `SessionView`, `EngineStatusView` (the diagnostics line), `EngineNotice` (the status line under the sidebar's filters: offline, rate limited, or stopped with Restart), `AppInfoView`, `AppearanceSettings` (theme and accent; in the account menu until Preferences exists), `ChannelIconPicker` (not wired yet), each with its props type.
- The topic view (M4, `docs/plans/m4.md` WP4), each a dumb view over the contract's `TopicDetail`, `MessageView`, `ThreadSummary` and `Person`:
  - `TopicView` (the frame: `header`, the list as children, an optional `pill` floated over the list's bottom edge, and the `composer` slot at the bottom).
  - `TopicHeader` (context pill, the stealth pill with its Mark read button, Main's "Threads" button with its `Popover` and the `threads` content, the Subscribe bell, then the 32px `art` slot and the title: "#eng · Main" with its sub line, or the title with the AI sparkle and double-click rename through `onRename`). Pin, Resolve and More arrive in M5; the header leaves the room.
  - `MessageList` (the centred 800px column in a `ScrollArea`; rows in flow with `content-visibility: auto`; the "N new" divider before `dividerBefore`; the fixed "Loading older messages" slot; the loading, offline and empty states; a roving tabindex with arrow keys; `scrollRef` and `anchorRef` for the container, which owns every scroll decision; `renderToolbar` for the hover toolbar, which the app does not pass until M6).
  - `Message` (memoized; the avatar column with the time on hover for a continuation, the name and time on a group start, the body, files, reactions, Main's thread link, the mention tint, and the reserved toolbar slot inside the row's box), `MessageBody` (paragraphs, quotes, code, lists, headings, rules; `@person` chips in the person's hue, `@you` in the accent, `#channel` chips that call `onChannel`, links through `onLink`, custom emoji, `date` elements formatted in the reader's time zone; an emoji-only message is drawn larger), `Reactions` (chips; plain labels until `onToggle` is given), `Files` in `FileCard.tsx` (a thumbnail in a box of its final size from `thumb`'s dimensions, a fixed-height card otherwise), `ThreadLink` ("2 replies · Title ›", mouse-down activation), `NewDivider`, `NewMessagesPill` ("2 new messages" or "Jump to latest"), `HoverToolbar` (quick reactions, More reactions, Quote, Reply in thread in Main; icon only), `ActiveThreads` (the list behind "Threads": title, reply count, time, unread count, Subscribe bell), `ComposerSlot` (inert, at the composer's single-line height).
  - `Workspace` now takes `tabs` (`WorkspaceTab`: id, title, a kind or page icon, `stealth`, and `art` for the 15px icon slot), `activeId` and the tab callbacks; with no tabs it shows the empty state.
- `relativeTime(at, now)`, `messageTime(at, now)` ("9:12", "Yesterday", "Sat", "Oct 3"), `fullTime(at)` (the tooltip), `slackDate(timestamp, format, now)` (a Slack `date` element's tokens), `hueFor`, `initials`: formatting helpers, repeated from `@juno/domain` where domain has them because views cannot depend on it.
- `src/fixtures/topics.ts`: invented `TopicRow` view models shaped like the fake Slack seed, shared by the sidebar and row fixtures. `src/fixtures/messages.ts`: invented headers, message windows (a long thread, Main with thread links, mentions of you, right-to-left, emoji only, hostile content, files) and active threads, with builders for bodies, reactions and files. `PENDING_PICTURE` points at the request the gallery server holds open, for a thumbnail that never arrives.
- Copy lives in the views and their fixtures and follows `docs/design/friendly-layer.md` §7 within SPEC §17: short titles, one-sentence bodies, no exclamation marks, "Juno" or "I" only on the sign-in and Juno surfaces.
- `applyTheme`, `accentNames`, `defaultAccent`, `AccentName`, `ThemeName`, re-exported from `@juno/ui`. The desktop app does not depend on `ui`, so it reaches the theme entry point here.
- `@juno/views/fixtures`: `fixtures`, every view's fixture sets keyed by view name. The gallery renders them, and each gets a screenshot in light and dark.

Every view has a `<View>.fixtures.tsx` next to it, registered in `src/fixtures.ts`. Group its states under headings in product words (`Data: loading, empty, error, long`; `Session: expired`) as `@juno/ui`'s README shows. List only states the view's container can produce today: the lines and props its container passes, not copy it might pass later. A loading state holds still; nothing resolves on a timer.

## Must not

- Import `@juno/state`, `@juno/engine`, `@juno/store`, `electron`, Node built-ins or `effect` (`check-deps` enforces this for any `views/` directory).
- Mention `window.juno`. A container passes a callback.
- Hold state beyond local UI state such as a hovered or open flag.
- Use raw colours or sizes. Values come from `@juno/tokens` through `@juno/ui` primitives; see the stylex skill.
- Take `style` or `className`.

## Testing

Visual and behaviour checks run in the gallery, not in the package: `pnpm gallery` to look, `pnpm gallery:shots` for screenshots, `pnpm test:gallery` for behaviour (mouse-down activation, cursor rule, state switcher, no layout shift on hover, press or focus, and a message thumbnail that arrives late or fails). In the gallery a view is one state per address (`#/SignInView?__state=failure/keychain`), and `j` `k` `[` `]` move between states and components. A view's user flow is covered by an e2e spec against the built app.
