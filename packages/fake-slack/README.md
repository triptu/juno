# @juno/fake-slack

A fake Slack for tests and development: an HTTP and websocket server that speaks the web client's protocol (`docs/research/slack-data-access.md`), with a control API to make things happen from "another client". See `docs/architecture.md` sections 2.2 and 13.

## Public API

```ts
const fake = await startFakeSlack({ port?, now?, seed? })
const { url, token, cookie, teamId, userId } = fake.credentials()
await fake.close()
```

- Server: multipart `POST /api/<method>` with the `token` field and the `d` cookie, `ok: false` errors, the edge API with JSON bodies, uploads, and the event socket with `hello` and ping.
- Uploads follow the official client's composer flow: `files.getUploadURL` gives `{ upload_url, file }`; the bytes go to `upload_url` as multipart with one field named `file` (a raw body works too; no token or cookie); `files.completeUpload` sets titles; `files.share` posts one message by self with the files, `client_msg_id`, blocks or a plain `comment`, in a channel or a thread (`broadcast` for a reply broadcast), with the same socket events as `chat.postMessage`. `files.share` reads `files` comma-joined, as the client sends it, or as a JSON array. `files.info { file }` answers the file as it is now. Errors: `file_not_found` (unknown id or no bytes yet), `channel_not_found`, `not_in_channel`, `thread_not_found`.
- File objects carry the type (image magic bytes first, then the part's Content-Type, then the extension), the size, and for PNG, JPEG, GIF and WebP the original size read from the header plus Slack's thumbnails: square `thumb_64`, `thumb_80`, `thumb_160`, `thumb_360` always, and each of 480, 720, 800, 960 and 1024 only when the long side is above the size before it, each fitted to its box and never upscaled. Thumb urls serve the original bytes. `GET /files/<id>/<name>` requires the `d` cookie (a bearer token alone redirects to sign-in) and serves the bytes; `?download=1` adds `content-disposition: attachment`.
- The default seed has an image (`early-access-flow.png`, 960 x 640) and a PDF (`q4-plan.pdf`) in the #product thread "Proposal: cut offline mode and public API v3 from Q4", exported as `EARLY_ACCESS_PNG` and `Q4_PLAN_PDF`.
- `usergroups.list` returns every group, deleted ones (`date_delete` > 0) only with `include_disabled`, with no `users` and no paging, as live. The default seed has two live groups and one deleted; messages mention them as the bare `<!subteam^S…>` Slack sends.
- `presence.set` accepts `active` or `away` and emits `manual_presence_change` for the self user.
- Presence as colleagues see it (`selfPresence()`): the self user is active while one of their sockets is open, their `manual_presence` is `active` and a `tickle` came within `AUTO_AWAY_MILLIS` (10 minutes on the fake's clock; Slack's real timeout is unknown). Every frame a client sends other than `ping` is recorded in `received`, apart from `calls`.
- Controls, each also reachable as `POST /control/<name>` for tests that drive a built app: `injectMessage`, `editMessage`, `deleteMessage`, `markRead`, `markThreadRead`, `followThread`, `unfollowThread` (self, from another client), `setSelfUsergroups`, `putUsergroup` (adds or changes a group; emits `subteam_created` or `subteam_updated`), `addReaction`, `removeReaction`, `joinChannel`, `leaveChannel`, `renameChannel`, `typing`, `emitFrame`, `dropSocket`, `goOffline` and `goOnline` (sockets are dropped and refused in between, so events reach no client), `force429`, `clear429`, `forceError` (the next calls of a method answer `ok: false` with a given error, before the handler runs), `clearError`, `holdNext` (the next calls of a method run their handler, or take their forced error, but answer only on `release`, so a test can land events while a page is in flight; with `before` they wait before the handler runs, so Slack has not seen them yet), `release`, `heldCount`, `heldCalls`, `loseResponse` (the next calls of a method run their handler, then the connection closes with no answer: an accepted call whose answer was lost), `holdFrames` and `releaseFrames` (frames of given types wait, then are sent in order or dropped, so an event can arrive late or never), `heldFrames`, `delayFiles` (file downloads answer after a delay, so images arrive late), `setLatency` (every Web API and edge call waits a fixed time before it runs, like a real network; also the `latencyMillis` start option), `failUploads` (the next upload POSTs answer HTTP 500 and keep nothing, so a client can fail and retry), `holdThumbnails` (files uploaded from now on, and `injectMedia` files, have no thumbnails, no poster and no size on the message and in `files.info`, as a fresh upload's echo has live) and `releaseThumbnails` (the held files get them, stored messages too, with a `file_thumbnail_generated` frame each; `event: 'file_change'` or `'none'`), `injectMedia` (another user's message with images and videos of given sizes; a video has a PNG poster at `?thumb=video`, `thumb_video` with its size and `mp4`; with `partial`, the socket event carries each file as Slack's partial copy, `file_access: "check_file_info"`, while history and `files.info` have it whole), `expireSession`, `advanceClock`, `setNow`, `resetCalls`.
- Where the fake is stricter than it looks, because real Slack is (research sections 2 and 10): `subscriptions.thread.getView` returns at most 10 threads per page whatever `limit` says; `search.modules.messages` orders by relevance (a stable shuffle) unless asked for `sort=timestamp`, pages by number without a cursor, and includes `thread_ts` and root `reply_count` when `extra_message_data=1` (otherwise a reply names its thread only in the permalink), and carries no blocks, no files and no reactions; `client.counts` with `counts_last_fetched` lists only the conversations that changed since then; a reply by self follows the thread and sends `thread_subscribed`; `channel_rename` and `group_rename` carry a partial channel object (`id`, `name`, `name_normalized`, `created`).
- In-process only, for tests that choose the order in which Slack decides each call (the conformance replay, `packages/engine/test/conformance`): `gate(where)` stops every API call `where` matches twice, before its handler runs and before its answer; `gated()` lists the waiting calls, each with one id for both stops; `decide(id, decision)` runs, refuses (`{ error, status?, retryAfter? }`) or drops a call at its first stop, and answers or loses it at its second; `gate()` with no argument lets waiting calls go on. `holdFramesWhere(where)` and `releaseFramesWhere(where, drop)` hold and send, or drop, the frames a predicate picks.
- Two plain pages outside Slack for the web panel, with no auth: `GET /web/page` (titled "Fake page") and `GET /web/other`, each linking to the other. Tests link to them instead of the real web.
- Inspection: `calls`, `callCount(method)`, `frames`, `received` (frames from clients), `selfPresence()`, `messages(channel)`, `socketCount()`.
- A sign-in page that sets the `d` cookie and `localStorage.localConfig_v2`, as the real one does from Juno's point of view. The `enterpriseId` option makes the team an Enterprise Grid one.
- `writeSlackAppFixture(dir, { team, cookie, keychainPassword, cookiesFile?, signedOut?, emptyTeams? })`: a stand-in for the installed Slack app's data directory (leveldb with `localConfig_v2`, a Chromium cookie store at `Cookies` or `Network/Cookies` with the encrypted `d` cookie, or without it when `signedOut`), for testing the import path.
- `topic300Seed()` creates a 300-message thread and a separate 300-message Main, with exactly 20 % dimensioned images and 10 % code blocks in each. It returns `{ mainId, threadId, threadTs }`; `TOPIC300_MAIN_CHANNEL` and `TOPIC300_THREAD_CHANNEL` name their channels. Image URLs serve fixture SVG bytes. `workspace.emoji` supplies the edge emoji list.
- A default seeded workspace (`PEOPLE`, `CONVERSATIONS`); replace it with the `seed` option. It includes public channels the self user is not a member of (`members` without `SELF_ID`), because the real `client.userBoot` lists every channel of the workspace.
- Boot shapes follow what the live smoke recorded (`packages/slack-schema/test/fixtures/recorded/`): `client.userBoot.channels` is metadata only for every channel, member or not (no `is_member`, `last_read`, `latest`, `unread_count`); `client.counts` lists the user's own conversations with their read state. `conversations.*` and the `channel_joined` family return the fuller channel object with `is_member`. The socket sends `hello` with `start: true`, then a complete `reconnect_url` after 200 ms and every 30 s.
- `pnpm --filter @juno/fake-slack start` runs it on its own.

## Must not

- Import the engine, the client (`@juno/slack`) or any UI package. It depends on `@juno/slack-schema` only, and encodes its responses with those schemas so it cannot drift from the client.
- Be imported from `src` of another package. It is a `devDependency` for tests (`testDeps`).
- Contain real Slack tokens, cookies or message content. Fixtures are invented.

## Testing

`pnpm --filter @juno/fake-slack test`. The tests call the fake over real HTTP and websockets: auth failures, pagination, posting and echoes, the upload flow, and each control. Any behaviour the client tests rely on is checked here first.

`holdNext`, `heldCount` and `release` also cover edge methods using the `edge:` prefix, for example `edge:users/info`. This lets desktop tests delay sender resolution independently of history. Use `file:bytes` to hold thumbnail or download bytes until the test explicitly releases them.

`unfurlFixtures(base)` supplies invented X image/text posts, failed images, YouTube, GitHub, Google Docs and generic previews. Avatar responses require the fake session cookie, so desktop tests exercise the authenticated image path.
