# @juno/state

The renderer's bridge to the engine: its client and every atom. The only package that imports `effect/reactivity` Atom and `@effect/atom-react`, and the only place the renderer touches `effect/rpc` and `effect/workers`. See `docs/architecture.md` section 7.

## Public API

- `liveQuery(route)(payload)`: an atom for a stream route. A `liveValueRoute` gives the latest value; a `liveListRoute` gives a `ListWindow` kept by `applyListDelta`. Memoized per route. The atom keeps its subscription for a 30 s idle TTL after the last reader leaves.
- `applyListDelta`: rows with an unchanged `rev` keep their objects, across a `reset` too (a reconnect re-renders only what changed); `order` keeps its array when equal. The delta's `refs` (the people, channels and topic art rows name by id, architecture 7) go into `window.refs.people`, `window.refs.channels` and `window.refs.art` before the rows; a ref that arrives equal to the one held keeps its object, and a delta without refs keeps the maps.
- `command(route)`: a writable atom that runs the command and exposes its `AsyncResult`. It runs one call at a time: a second write interrupts the first, so per-row actions use `runCommand(registry, route, payload)`, which gives each call its own atom.
- `prefetch(registry, atoms)`: warms one or more queries as one entry (hover, focus, keyboard selection). One warm set per registry, at most three entries; it holds the subscriptions under the atoms, not the atoms, so an evicted prefetch that was never opened ends at once. An open topic reads the atoms themselves and is never evicted.
- `@juno/state/socket`: `configureSocketConnection(registry, url)` selects the web shell’s WebSocket protocol. Only the web page imports it; Electron keeps the port protocol.
- `registry`, `makeRegistry()`, `configureConnection(registry, { acquire })`, `connectionStateAtom`, `acquireRendererPort`: the client and its connection. Tests make their own registry. `restartEngine(registry)` asks main to start the engine again after its supervisor gave up (`failed`); the transport keeps asking for a port and connects once one comes.
- Feature atoms, declared once at module level in `src/<feature>.ts`: `engineStatusAtom`, `pingCommand`, `appInfoAtom`, `themeAtom`, `persistTheme`, `sessionStatusAtom` and `signedInAtom` (the last ready session, held while the engine restarts so the shell stays up), `topicListAtom(filter)` (one filter's window, with each wire row's channel and people joined from the refs into the `TopicRow` the views take; a joined row keeps its object while its wire row and what it names keep theirs), `topicCountsAtom(scope)`.
- Topic view atoms in `src/messages.ts`:
  - `messagesAtom(id, window)`, `topicAtom(id)` (`TopicDetail | null`) and `channelThreadsAtom(channel)`: the live queries.
  - `messageWindowSpecAtom(id)`: the window a tab wants (`{ anchor?, before?, limit }`, the bottom 150 by default). The container writes it.
  - `messageListAtom(id)`: the window shown. When the spec changes it keeps the old window until the new one's first snapshot arrives, then swaps in one update; rows with an unchanged `rev` keep their objects.
  - `openTopic(registry, id)`, `loadOlderMessages(registry, id, before)`: the commands that call Slack. `prefetchTopic(registry, id)` warms the header and the window a tab would show, as one prefetch entry, with no Slack call.
- Tabs in `src/tabs.ts` (spec section 6, inventory 4, performance 4.3):
  - A `Tab` has its own id, a `pinned` flag, and a `history` of `Place`s (a topic or a page) with the index it shows. The pure rules over `Tabs` (`{ tabs, active, recent, closed }`): `openPlace` (the current tab as a new history entry, or a new tab after it with `newTab`; a topic another tab shows focuses that tab), `stepHistory` and `goToEntry` (Back, Forward, the history menu), `historyTarget`, `closeTab`, `closeOtherTabs`, `closeTabsToRight` and `closeAllTabs` (the bulk closes leave pinned tabs), `reopenClosedTab` (⌘⇧T, a stack of 20), `setPinned`, `activateTab`, `cycleTab`, `tabByNumber` (⌘1 to ⌘9), `mountedTabs` (the active tab and the 4 most recent), `dividerIndex(order, lastReadTs)`, `parseTabs`.
  - `tabsAtom`: the signed-in workspace's tabs, read back from the `tabs` workspace preference after a restart (each tab with the place it shows; history and the reopen stack are in memory only). `updateTabs(registry, rule)` applies a rule and saves the result; nothing else changes them.
  - `tabStripAtom`: the tabs with their `TopicDetail`, for the strip and its unread dot. `historyStateAtom`: whether the active tab can go Back and Forward. `scrollSnapshotAtom(topicId)`: where a topic was scrolled, kept while the app runs.
- `slackLink(workspaceUrl, topic)` in `src/links.ts`: a topic's Slack link, built with no API call. `messageLink(workspaceUrl, channel, ts, threadTs?)` is a message's.
- `runAction(registry, route, payload, toast)` and `undoLast(registry)` in `src/undo.ts`: run a user's action, keep the undo the engine returned (`undoStackAtom`, at most 20) and show the toast (`toastAtom`); replay the newest undo on ⌘Z or the toast's Undo (ADR 0010). `offerUndo(registry, undo, toast)` does the keeping and the toast for a caller whose words depend on the command's answer (Edit channel's Save).
- `channelSheetAtom` in `src/channels.ts`: the channel sheet (SPEC 5, "Channel sheet"), closed, a new channel with ⌘K's text, or a channel to edit with what the user may change in it.
- `renamingAtom`, `rowRenamingAtom(id)` and `headerRenamingAtom(id)` in `src/rename.ts`: which title is a field for Rename.
- Sidebar state in `src/sidebar.ts`, none of it persisted. The list container and its rows read only these:
  - `sidebarFilterAtom` (kind, unread, scope) and `selectedTopicAtom`.
  - `sidebarListAtom`: the window shown, a `SidebarWindow` (`ListWindow<TopicRow>` plus the `filter` it belongs to). After a filter change it keeps the old window until the new filter's first snapshot arrives, then replaces it in one update, never with an empty list in between. A row whose `rev` and read state are unchanged keeps its object across the swap. Read-dependent lists retain previously visible open topics until no tab currently shows them; retained rows keep their place and take live read state from `topicAtom`. Filter changes clear retention. While the pointer or keyboard focus is in the list it holds its order (`holdOrder`, SPEC 5): the list container calls `setSidebarEngaged`, own actions call `releaseSidebarTopic` for their row, and opens from elsewhere, Undo and Ignore channel call `flushSidebar`. Tests only: `sidebarTrace.ts` records each change of the hold's inputs and each list value when the e2e harness asks (`traceSidebarHold`; `apps/desktop/e2e/README.md`, "Sidebar trace"). `sendTrace.ts` likewise records a send's path, the tab changes and each topic view's new message windows (`traceSend`; README, "Send trace").
  - `sidebarSectionsAtom` (`sidebarSections.ts`): `{ ready, pinned, recent, total, filter, retained, moves }`, the shown window's ids split into Pinned and Recent. Equal splits do not notify. Use its `filter`, not `sidebarFilterAtom`, to pick the empty state. `moves` says whether the change to this split may slide on screen (`animate`, a change from elsewhere) or shows in one frame (`instant`): `sidebarMoves.ts` is a pure rule loaded on idle by `loadSidebarMoves`; before that, changes are instant. Command writes arrive as `meta.own` from the engine, so elapsed time cannot misclassify a slow command or a subsequent outside reply. Synchronous releases (`releaseSidebarTopic`, `flushSidebar`, sheet close) batch their generation stamp with the release. Internal bookkeeping retains tab-retention changes even when equal splits do not notify.
  - `sidebarRowAtom(id)`: one row, keyed by id alone, so a row keeps its atom and its component across filters and notifies only when its object changes.
  - `focusedTopicAtom`: the row that had focus last. The list container sets it when a row gets focus.
  - `topicSelectedAtom(id)` and `currentRowAtom(id)`: booleans for "selected" and "takes Tab focus" (the row focused last while it is shown, else the selection while it is shown, else the first row). Only the rows whose answer changes are notified.
  - `sidebarDotAtom('channels' | 'dms')`: whether that filter shows a dot, from the counts of the current scope, as a boolean.
  - `nowAtom`: wall-clock milliseconds, refreshed on each minute boundary while something reads it. Read it through a selector that returns the label, `useAtomValue(nowAtom, (now) => relativeTime(at, now))`, so a tick re-renders only rows whose label changed.
- Topic art in `src/art.ts`: `redrawTopic(registry, id, toast)` runs `art.redraw`, keeps its undo and resolves with why it made no drawing (`RedrawProblem`), or undefined. A sidebar row's `art` is joined from `refs.art` in `topicListAtom`; an empty recipe (AI assist off) joins as no art.
- `@juno/state/agent`: the Juno chat, over the agent's own port (ADR 0012, plan v3 §12).
  - `configureAgentConnection(registry, { acquire: acquireAgentPort })`, `agentConnectionStateAtom` (`off` while main says no agent runs; the transport keeps asking), `AgentClient`.
  - `chatPageAtom(window)`: the agent's `ChatPageSnapshot` for a window (`latest`, `unread`, `around`, `above`, `below`), with each card's binding beside the view. `chatItemsAtom(window)`: the same `ChatPage` with the sends the agent has not stored yet, which is what the list renders. `chatSummaryAtom`: unread count, busy and job line.
  - `chatActions(registry)`: `send(text, { context?, replyTo? })` mints the op id (UUIDv7) and shows the bubble at once as `sending`; the agent's row replaces it after the inbox commit; a failed write shows `failed: notDelivered` and a text over 64 KB `failed: tooLong` without a call. `onRetry(opId)` resends a send that was not stored with the same op, or asks the agent to resend an interrupted or failed message. `react`, `read(through)` and `onCard(id, command)`: a card command maps to the card RPCs with the binding from the last page (Send rows edited first, a choice prepared, then approved; `signIn` is the container's). `onRetry` and `onCard` match the views' `ChatActions`.
- Home's greeting and scene in `src/homeScene.ts`: `homeGreeting`, `homeScene` (the copy and the scene from the local clock, the home README's rules) and `homeAppeared` (the first visit of a day, for the seasonal scene).
- Home in `src/home.ts`: `homeViewAtom` (`home.view`), `prefetchHome(registry)` (warms `home.view` from the sidebar's Home button, one `prefetch` entry), `freezeHome(shown, latest)` (the rows Home showed, with only their new `aiTitle` and topic art), `fillHome` and `addHomeItems` (during the first sync, before and after Home is ready, items fill reserved slots below the rows shown), `homeItemLimit` (the cap from the window), `startVisitLog(registry)` (records the active topic with `home.visit` after `VISIT_MILLIS` on screen and when it leaves), `markFollowUpDone` and `resolveAllTopics` (one `topics.restoreAll` undo and the "Resolved 3 topics" toast), `actOnSettled` (a Tidy up row), and `markMovesShown`, `markMovesSeen` and `actOnMove` (Automated's record: shown at most once a day, and not again by a Home opened before the engine's next view arrives, its moves seen once opened or dismissed, and Move back or Keep through `views.sortChannel`).
- `@juno/state/react`: `useAtomValue`, `useAtom`, `useAtomSet`, `useAtomRefresh`, `RegistryContext`. Containers import hooks only from here.
- `@juno/state/perf`: the fixed performance marks and `observeFrames()`. `juno.live-update` is measured for every live message and replaces the previous entry, so the buffer holds the latest one only.

Transport errors are retried every second and never reach an atom. Route errors reach it typed.

## Must not

- Contain JSX or import React components. Only the hooks module touches React.
- Use the DOM lib. It must typecheck without it because the engine's tests import it; reach browser globals through `globalThis` with local types.
- Import `@juno/engine` or `@juno/views`. It depends on `@juno/contract` and `@juno/agent-contract` only.
- Be bypassed: nothing outside the allow-list imports Atom, `effect/rpc` or `effect/workers` (`check-deps` enforces it).

## Testing

`bun run --cwd packages/state test` covers `applyListDelta` (identity of unchanged rows, order, removal, reset, refs), the sidebar and Home hold rules and the tab rules. `test/tabs.model.test.ts` runs 300 seeded random sequences of tab operations and checks the invariants after every step (unique ids never given out twice, pinned first, the active tab open, recent and mounted tabs, the history and reopen limits, a save and restart, ⌘W then ⌘⇧T); a failure prints its seed and steps. Named examples there cover where a tab opens and the formats older builds saved. The peek key, the read rule, expiry and the chat's size limit are covered end to end by `peek.spec.ts`, `topic.spec.ts` and `mark-unread.spec.ts`, `tabs.spec.ts` and `juno-agent/states.spec.ts`. The topic view atoms are tested end to end in `packages/engine/test/flows/topic-view.flow.test.ts`. The client and helpers are tested end to end in `packages/engine/test/protocol.test.ts`, and the sidebar atoms in `packages/engine/test/flows/sidebar.flow.test.ts`; both use a registry per test and a Node `MessageChannel` in place of the renderer's port. `test/agent-chat.test.ts` runs the chat atoms and actions against the agent's real renderer server and turn engine (`@juno/agent` and `@juno/agent-testing` are test-only dependencies).

Task commands retain the job id even without an approval binding. Stop uses
the job RPC, which approves one interrupt under that click's op id. Expired
cards retain only the identity Ask again needs; that RPC submits a fresh
owner message quoting the card. It never approves the expired payload.

`composerEmojiAtom(open)` shares the workspace emoji query between colon suggestions, reaction pickers and Settings. `@juno/state/emoji` loads with the picker chunk, retains one subscription, and prepares canonical aliases and search data once per table change. Containers schedule index warmup after paint with an idle timeout, pass readiness to the dumb picker view, and show name matches while it warms. Pickers show standard emoji immediately and add Workspace last when its data arrives. `recentEmojiAtom` reads local choices through `emoji.recent`. `frequentEmojiAtom` reads the final picker names through `emoji.frequent`, loaded after the first sidebar paint and kept for the session. `noteRecentEmoji` sends `emoji.use`; the engine saves the choice. The engine ranks Frequently used from local choices, Slack's cached usage counts, then quick reactions; a picker opened before the list arrives shows the user's quick reactions alone. Its names have cells from the first paint and keep their order until close; workspace images fill those cells without changing the row geometry. Juno badges resolve only their displayed names from its prepared lookup, without a live subscription. State validates the table JSON with the normal contract Schema decoder.

On an empty cache, the sidebar holds its first rows until the cold boot's quick start (membership, the people of the DMs, the first page of followed threads) is stored; rows then fill in as the sync stores them, each in its place by recency, without a reload. A cached window paints immediately. While catch-up fills the sidebar, existing rows retain their order and newly discovered rows append. The phase becoming live does not itself reorder the painted list. An explicit filter change or the next live activity uses the normal recency order again.

All topics also holds its first rows on an empty cache until the quick start is stored; cached and filtered windows keep the existing snapshot handoff.

Each Home tab's draft and destination are `homeDraftAtom(tabId)` in `src/homeDraft.ts`, saved with the tab (`setHomeDraft`); `requestHomeFocus` asks a Home tab's composer for focus (⌘N, ⌘T).

A thread started by a send keeps its pending `viewId` when `acknowledgeTopic` replaces the topic ID in open and closed tab history. The view key preserves the message subscription, composer and scroll position; it is saved with the tab for reopening.

The ⌘K Conversations tab's `newChat.ranked` live query ranks the same way over own sends and topic visits (`topic_visits`), uncapped before its 12 rows, then by activity; with text it ranks the conversation picker's matches, names that start with the text first among the unused. It re-runs on conversation, user, ignore and visit changes, not on messages, so a send re-ranks it on the next open. The renderer reads it as `paletteConversationsAtom`.

`diagnosticDetails` reads the safe process log tails and engine outbox aggregates for Copy diagnostics. `showLogs` opens the logs through main.

The agent client uses a scoped `Context.Service` and `Atom.runtime`. `agent/rpc.ts` loads the RPC schemas and creates the flattened client on demand; the workspace also preloads it on idle when Juno is available. All streams and commands share the same runtime and port.

The Search tab's state is `search.ts`: `searchSessionAtom(sessionId)` (the field, scope, sort, selection, whether the topic panel shows, and scroll, saved with its tab), `searchPrefsAtom` (Apps hidden, Automated hidden, the topic panel's width), `recentSearchesAtom`, and `searchResultsAtom(sessionId)`, which subscribes through `searchSnapshots` with a generation that only grows, folds group deltas by id and keeps the last snapshot until the next one arrives (`docs/architecture.md`, "The Search tab").

Search streams have zero idle TTL: hiding, closing or clearing the tab cancels its remote work immediately. Typed input, including the first character, waits 400 ms before Slack; restore, commit and filter actions are immediate. `searchMatchesAtom` reads bounded reader navigation metadata from the engine.
