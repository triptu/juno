## Crash points

All 16 names in `packages/agent/src/runtime/crash.ts` have scenarios:

- `inbox.committed`, `bridge.reset`, `bridge.submitted`: preserve both exchanges without duplicate bubbles.
- `approval.committed`: apply the durable approval once.
- `authorization.consumed`: show Failed and never send the consumed authorization.
- `attempt.beforeReceipt`: the fake receives one write; recovery never repeats it.
- `rotation.drained`, `rotation.committed`: keep a completed write, an open card and both exchanges across rotation.
- `redaction.deletionRaised`, `redaction.committed`, `redaction.purged`: distinguish an uncommitted removal from a durable removal and finish recovery.
- `backup.segmentWritten`, `backup.manifestRenamed`: keep the completed write and open card; finish a backup without another write.
- `ownership.released`: publish the move code after restarting and stay read-only.
- `restore.staged`, `restore.swapped`: restore the chat and open card, wait for review, then resume.

The runtime performs SIGKILL itself. `restartArmed` arms only the replacement utility process and removes the setting after the crash, preserving main's in-memory fake keychain. It does not change app code. Interrupted Move/Restore sheets are dismissed with Escape after recovery.

Rotation ages the persisted incarnation before the replacement process opens it. Schedule tests move the saved due time into the past while the app is closed. This avoids real-time waits, but is not an injected app-wide clock. The interrupted-state test removes the closed journal to exercise recovery from missing journal data.

## Remaining product and coverage gaps

### Reproduced approval-binding bugs

Both remain executable `test.fixme` cases. They must not be counted as passing coverage.

- **Task Stop** (`t3.spec.ts`, “Stop on the Task card interrupts the session”): connect fake T3, approve Start, wait for the running Task card, then click **Stop**. The first failing assertion polls fake T3's thread status for `interrupted`; it remains `running`, with no `t3_thread_interrupt` call. `packages/agent/src/serve/chat.ts` builds `task:<jobId>` cards from jobs without approval bindings. In `packages/state/src/agent/chat.ts`, `rememberCards` iterates only the bindings, so it never records that Task card. `cardCommand` returns `unknownCard` before its `stop` branch can call `agent.jobs.stop`. The fix needs to let task commands resolve a job independently of an approval binding; the regression also expects the UI to become Stopped and exactly one interrupt.
- **Expired-card Ask again** (`cards.spec.ts`, “an old unapproved card expires…”): propose a Send card, close the app, age its persisted creation time, relaunch, verify Expired, then click **Ask again**. The first failing assertion expects one owner bubble saying “Ask again”; none appears and no new model request is sent. The expired card has no binding in `agent.chat.page` (`packages/agent/src/serve/server.ts` filters absent bindings). The same `rememberCards` / `cardCommand` path returns `unknownCard` before `agent.cards.askAgain`. That server handler already accepts an expired card and enqueues a new owner message with a card reply target. The renderer needs an identity for that command without requiring a live approval. The regression expects a second, open card and zero Slack sends.
