# WP22 coverage

WP22 follows plan-v3 §16 and SPEC §13. All checks use fake Slack, a scripted
model and fake MCP servers. Skipped tests are not passing coverage.

## Covered flows

- Chat send, working and failure states; steering during a run; typed “stop” as a message.
- Multi-send with one failed post, per-row outcomes and Activity decisions.
- Expired-card Ask again after relaunch creates a fresh proposal without sending.
- T3 Start, Task Stop, pending questions and answers, Task Open and the structured PR link.
- Loopback preference, secret-blocked copy and a Because line for tainted T3 instructions.
- Scheduled wakes across relaunches, Scheduled group labels, controls and reply cancellation.
- The message-menu reply watch and its Undo, with no model run.
- Custom-address Notion and Littlebird connections, including explicit reclassification of an unknown tool.
- Remember, selected-span menu pinning, editing, Undo, removal and masked/rebuilt memory.
- Budget Allow and Wait, provider catalogue filtering, Pause, AI off and offline waiting.
- Cooperative move and recovery, plus all 16 named runtime crash points.

The `card-bindings` branch merged `origin/main` at `4a35b2ed48` in `7e6e3376`,
then at `e940effc` in `cbd8867d`. These merges include Slack writes,
Remember/Remove, network admission and the search palette. The
card fixes preserve command identity independently of a live approval binding.
Task Stop uses its own operation id; Ask again never re-authorizes the old card.
The real T3 tool schemas and fake now agree on `requestIds`, `questions` and
answers keyed by question id. Activity now projects each Send-card child
separately, preserving the successful post when another post fails.
